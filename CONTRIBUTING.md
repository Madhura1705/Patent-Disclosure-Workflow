# Contributing Guidelines

## Branch Naming Rules

Use the following naming conventions:

- `feature/<short-description>` – new functionality
- `bugfix/<short-description>` – defect correction
- `hotfix/<short-description>` – urgent production correction
- `docs/<short-description>` – documentation changes

## Commit Message Convention

Use short, meaningful commit messages such as:

- `feat: add status tracking`
- `fix: correct validation`
- `test: add Selenium test`
- `docs: update project documentation`
- `ci: update Jenkins pipeline`

## Pull Request Rules

1. Create a feature/bugfix/docs branch from `main`.
2. Commit related changes with meaningful messages.
3. Push the branch to GitHub.
4. Create a pull request targeting `main`.
5. Review the changed files and resolve comments.
6. Merge only after validation/tests pass.
